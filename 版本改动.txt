这个版本改了什么（v2.0.15）
============================================================

一、根因：代码创建的控件把「当时那只画刷」存进了属性
ApplyProfile 每次换角色都会重建 brushInk / brushMuted / brushAccent / brushLine / brushSoft / brushCard 并刷新 Window Resources，
但 ShowPage 会把页面缓存进 pageContainers，角色切换不重建页面；而 WrapField、BuildHistory、ShowRecordDetail、BuildRecordCard
这些地方创建控件时写的是当时的 IBrush 实例。实例不会因为字段后来被重新赋值而变化，于是出现「先切 Claude 再切 DeepSeek，
外框还是橙的」这类残留。ApplyTextTheme 只改前景色，管不到 BorderBrush / Background。

二、做法：一个轻量的主题控件登记表（不重建页面）
- 新增 themeBoundControls（WeakReference 列表）+ BindTheme(control, line/card/soft/ink/muted/accent) + RefreshBoundThemeControls()。
  BindTheme 用 Classes（theme-line-bound 等）标记每个控件要跟哪几路画刷，并用 theme-bound 类去重，避免同一控件重复登记。
  WeakReference 让页面反复刷新时旧控件能被回收。
- ApplyProfile 里在六只画刷与 Resources 全部更新完之后、ApplyTextTheme 之前调用 RefreshBoundThemeControls()。
  页面缓存、编辑器实例、正文内容一律不动。
- 登记范围：WrapField 返回的外框（留言/交接正文框）、回忆长廊的 histSearch / histFilter / leftCard / detailCard、
  详情里的附件框与 编辑 / 回形针 / 垃圾桶 三颗按钮、记录卡片外框、以及 MakeIconButton 内部的 Path 图标（按 accent 或 ink 登记）。
- MakeIconButton 的悬停事件不再捕获旧画刷：改为事件触发时读 brushAccent / brushInk / brushLine 当前字段，
  因此换角色之后再悬停，颜色是新角色的。

三、没有动的
各角色 Accent、布局尺寸间距、保存逻辑、回忆长廊附件逻辑、搜索与筛选、数据格式、全局 TextBox 焦点框（ThemeLine + PART_BorderElement 那套）、
说明页贡献名单、页面缓存与编辑器实例。

四、实测（同一页面内连续切换，未重建页面）
A. 留言页正文框：GPT 淡紫 → Claude 淡橙 → DeepSeek 淡蓝 → 回 GPT 淡紫，四张连续截图均正确。
   切换前在正文里留了一段未保存文字，切到 DeepSeek 后文字仍在（正文框只换了边框色）。
B. 缓存页面：GPT → 回忆长廊 → Claude → DeepSeek，搜索框、筛选框、左右卡片、详情卡、附件框、编辑与图标按钮全部跟随角色。
C. 悬停：在 Grok 下悬停垃圾桶（黑色系）再切回 GPT 再悬停，图标与边框都是当前角色色，没有回到上一角色的旧色。
D. 功能回归：切栏、选记录、附件展开、搜索筛选均正常；本次未新增任何数据写入。

五、未验证
Ctrl+A / Ctrl+C 真按键（自动化发不进 Avalonia 窗口，只能人工确认）；125% / 150% 缩放下的观感。
测试钩子：--roles Claude,DeepSeek,GPT 会在同一页面内依次切换角色，仅用于验收，不带这个参数时完全不生效。

1) 左边两张卡片的「左右纵向边」对齐了

   右侧，中间留空。

4) 快速切换卡顿/像"没响应"
   切页时的数据刷新改成 Dispatcher 后台优先级排队：点击后先立刻高亮导航、

   另外修了一个副作用：重建列表会丢掉当前选中项，现在会记住选中行并恢复，
